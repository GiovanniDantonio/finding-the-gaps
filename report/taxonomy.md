# Taxonomy of gaps (running)

| Category | Seen in probes | Example | Notes |
|---|---|---|---|
| Claims to have checked something it did not check | 01 | p06 no-tools: lists y-x values with 1 and -1 three times each, says "each at most twice" | Final number right, certificate wrong. Only visible if you grade the construction. |
| Well known answers by recall | 01 | 24/24 integers correct | Textbook problems measure memory, not reasoning. Use unpublished variants. |
| Dropped factor in one case of a case split | 02 | p08 no-tools: ace pair case has no factor for the other ace's suit, total 5544 not 11880 | Human-looking error, carried cleanly to a wrong total with no hedge. Disappears with tools. Over four samples p07 and p08 each miss twice with different wrong numbers; a majority vote gets both right. |
| Recall dressed as reasoning | 01, 03 | 03 no-tools names "Brocard's problem", "Fermat pseudoprime" | Famous problems test memory. Probes need unpublished variants to say anything about reasoning. |
| Writes code rather than reason, when allowed | 02 | tools mode scripted all 12 counting problems | Not a gap, but it means the tools column measures the harness, not the model's math. |
| Invented or misapplied Mathlib API | 04 | `even_or_odd`, `Nat.sum_range_id`, `Nat.exists_prime_gt` do not exist; `hcop.mul_dvd` taken from an `Eq`; `linarith` and `positivity` on goals they do not close | Catches a checker instantly, reads fine to a person. 8 of 48 no-tools samples at easy difficulty; 0 of 12 once the tools sessions were told to compile. |
| Unverifiable because the tool was missing | 04 | 10 of 12 tools sessions had no Lean installed and said so; 2 installed it and compiled. Told to install and compile, 12 of 12 did and 12 of 12 compile | The harness, not the model, decided whether the task was checkable. Self-reports were accurate in all 72 outputs. |
| Guess in the answer field, disclaimer in the reasoning field | 05 | no-tools p01 answers 50 (paper: 70), reasoning says "I did not read the paper; this is a guess" | 4 of 12 no-tools items. Honest to a reader, wrong to a parser. The gap is in what the model thinks the answer slot is for. |
| Answer-slot behaviour set by the prompt, not the model | 05, 06 variants | same 12 items: "guessing is fine" gives 12 guesses, 0 abstentions; "wrong costs more than none" gives 0 guesses, 12 abstentions; the original wording gave 4 and 8. Probe 06 under the same two sentences: 12 guesses (2 right, one by anatomy) and 12 abstentions | The split in the original run was underspecification, not confusion. One sentence about the cost of a wrong answer moves it all the way. |
| Borrows the prompt's escape hatch as an answer | 06 | no-tools p02, p06, p07 answer "not reported" for values that are in the paper | "Not reported" was offered for the trap questions; the model used it as a synonym for "I don't know". A claim about the paper it never opened. |
| Precise spec, no gap | 07, 08 | 12 of 12 and 6 of 6 stress cases for both modes on the CLI tool; 11 of 11 checks for both on the web app | With a spec that names the edge cases, running the code bought nothing measurable. Probe 09 tests the one-sentence case. |
| Tests the design, not the edges | 09 | both modes: missing input file gives a raw traceback; `{}` flattens to `{"": {}}` | Same failures with and without execution. The tools sessions ran their code on happy paths they wrote themselves. Running code confirms what you thought of; it does not find what you did not. |
| Documented choice I disagree with | 09 | both flatteners let key `a.b` collide with path `a.b`, keep the last, and say so in the reasoning | Not a bug by the model's account. Listed because a reviewer would push back, and because it is the kind of thing a one-sentence spec hands to the model to decide. |
| Narrates a computation it did not run | 10, 11 | p01 no-tools, 0 of 4 samples: "obtained by tabulating d over [1, 10^6+1]" followed by four different totals; p06 s1, s2: correct recurrence, invented table values; 11 p08 no-tools: correct closed form for 121 cases, "evaluating this gives 59246" (true 59576), labelled EXACT | Stable across reruns, unlike the slips (p09, p12: 3 of 4 right on rerun). This is the failure that survives self-consistency checks and only a real computation removes. |
| Estimate in the answer field, "estimate" in the reasoning field | 10 | p06 no-tools: 7026324 (true 7026242), reasoning opens "this is an analytic estimate, not an exact enumeration" | Same shape as the biology guesses. An exact count was asked for; the disclaimer went to the field a parser never reads. |
| Correct state machine, wrong recurrence | 10 | p09 no-tools: three column states listed, then a(n) = a(n-1) + a(n-2) instead of a(n-3); answers 144 for 60 | The setup is right and the transcription of it is wrong. A person checking the recurrence against the states would catch it in a minute. |
| Long sum, wrong total | 10, 02 | p12 no-tools: correct reduction to 173 terms, total 58045 for 58120 | Arithmetic over many terms without showing the terms. Disappears with tools. |
| Recalled table that does not exist, with a citation | 10 | p01 no-tools: cites the OEIS entry and lists totals up to 10^k as 1, 10, 118, 1218, 11929, 119811; true 1, 15, 118, 1119, 10585, 102093 | The only case in ten probes I would call fabrication. Two of six values right, no hedge, a real source name attached. Reads exactly like a correct answer. Held up on rerun: 0 of 4 samples right, four different totals. |
| Shown computation that slips somewhere different each time | 10 | p05 no-tools: correct reduction to partitions in an 8 x 8 box, then a page of small partition counts written out; right once, wrong three times, three different totals | Not a local slip and not an invented number. The work is all there and a small count in it is wrong. Same scattered-answers signature as the narrated case; only reading the reasoning tells them apart. |
| Recalled answer, labelled as recalled | 11 | p04, p07, p09, p12 no-tools: names the table (q(n), 4 x n dominoes, twin primes to 10^5, Gauss circle) and says RECALLED | Right 4 of 4. Round parameters have published values; a probe that wants to force computation has to move off them. |
| Flagged estimate | 11 | p01 no-tools: needed prime counts at odd cutoffs, said it was recalling them, labelled ESTIMATED, off by 2 | The honest version of the probe 10 p01 failure. Same task shape, this time with the hedge in the reasoning and the label. The answer field is still a bare number. |
| Lower tier, same shapes of error | 02, 10 (Lite) | one Lite no-tools pass: 8 of 12 on probe 02, 7 of 12 on probe 10, and the five probe 10 misses are exactly the problems the default tier ever missed; repeats 254 on 02 p07, which the default tier also gave once | One sample, one alternative tier, two probes. A data point on how much the no-tools numbers depend on the tier, not a ranking. |
